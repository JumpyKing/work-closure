# work-order — 工作单与检查点

## 工作单字段

| 字段 | 含义 |
| --- | --- |
| 来源 | 授权者与依据的用户请求或事件 |
| 目标 | 要交付什么，判定成品的标准 |
| 级别 | S、M 或 L，以及定级理由（见 SKILL.md 定级） |
| 可编辑范围 | 允许写入的白名单目录或文件清单，越界即停 |
| 验收 | 可证伪的检查项，任一不符即为未完成 |
| 依赖 | 需要预先存在的可执行文件、profile 与输入 |
| 禁止重复项 | 上游已完成、不得重做的事项 |
| 停止条件 | 触发即进入 `blocked` 或 `stopped_root_cause` 的情形 |

## 检查点字段

task_id、workspace、级别与理由、计划版本、产物身份（S/M 为 commit SHA，不提交时为改后文件逐文件 SHA256 清单；L 为逐文件 SHA256 与集合摘要）、已验证项、缺失证据、审查状态、审查轮次（同一工作单同一验收范围累计，最多三轮，详见 review.md 轮次预算）、逐路审查记录（每一路各记一条：role、报告路径、报告 SHA256、所审基准、verdict、意见处置，经包装器的一路另记 summary 路径；各路不得共用一条记录）、下一动作、未知副作用、止损计数（按问题与按操作分别记连续失败，总尝试历史保留）。

已有项目业务账本不必为逐路审查记录改 schema：主对话可用既有字段表达，或以旁挂证据文件承载该记录，保持检查点单写与项目权威不变。

检查点是唯一权威状态源：换模型、代理或对话后先读检查点再行动。止损只看连续失败：同一问题连续修复加复验失败 3 轮、或同一操作连续 3 次失败即停止并做根因分析；连续计数只能在同一验收项实际通过并附证据后清零，总尝试历史保留；换模型、代理或对话都不能清零。

## 账本位置

项目自带账本时沿用项目既有位置。没有账本时写入 `~/.cursor/work-closure/tasks/` 下以 task_id 命名的单独目录中的 `checkpoint.json`，例如 `~/.cursor/work-closure/tasks/wc-20261016-install/checkpoint.json`。该文件只由主对话写入，子代理与被调用模型只读。

## 执行纪律

- `rtk` 是本闭环的依赖，真实位置 `~/.local/bin/rtk`。被委派模型发出的所有 shell 命令以 `rtk` 开头；对 rtk 未专门支持的命令，用 `rtk proxy` 包装执行。目标环境缺少 `rtk` 时置 `blocked`，不静默省略该规则。
- 该 rtk 前缀约束只针对 shell 命令；`scripts/run_cli.py` 用 Python subprocess 参数数组直接调用子进程，不是 shell，argv 数组内不嵌套 `rtk`，也不使用 `shell=True`。
- 辅助 Agent 位于用户级安装路径 `~/.cursor/agents/work-conductor.md`。
- 长任务由主对话通过 PM2 管理，只操作本任务进程，日志必须 nostream。
- 被委派模型不做安装，不改全局配置，不读取凭据；文档、代码与 summary 不写凭据。
- 首次运行或权限变化时先在隔离目录做 Read、Write、Bash canary，由主对话核对真实文件内容。

## 范围验收与快照审计

- S/M 由主对话用 `git status` 与 `git diff --stat` 核对改动只落在工作单白名单内；负载不在 git 中时，与改动前备份逐文件比对。L 级实现前后由主对话对工作单明确的工作目录与保护范围做快照：文件清单、类型、符号链接目标与内容哈希，结合既有版本差异审计；排除项必须在派发前明确写在工作单中。
- 白名单之外发现新增、删除、字节变化或链接目标变化时置 `blocked`：先核实变更归属与影响，不自动删除、回滚或覆盖他人变更。
- 本机制是范围验收：只覆盖工作单声明的目录与保护范围，不声称操作系统沙箱，不覆盖整台电脑；不读取凭据，不做全盘扫描。
- 规划 workspace 是本次真实任务目录；恢复仅指依据本闭环检查点继续，不恢复暂停的业务任务、后台自动化或未经授权的外部动作。

## 条件段落：仅限本 Skill 安装维护

以下步骤只在本 Skill 自身安装、更新或修复时执行，普通项目任务不做，也不作为收口条件：

- 包装器四情形：仅在 `scripts/run_cli.py` 本身有改动时执行。用受控的假事件流验证 `scripts/run_cli.py` 的四类行为——同事件精确匹配通过、model/provider 拆分事件判 `model_mismatch`、模型明确不符立即终止子进程并始终返回 3（真实 child 状态放 `child_exit_code`）、无任何模型事件返回 3。其中"无事件返回 3"的用例前提是子进程自身退出 0；子进程自身非零退出时属于自然非零退出，包装器原样透传真实退出码（既有测试覆盖无模型事件且退出 7 时保留 7）。
- 安装前负对照：仅首次安装时执行。目标安装位置已存在本 Skill 时停止；负对照提示必须返回 `WORK_CLOSURE_ABSENT`。
- 安装或更新后发现：三份副本 `~/.cursor/skills/work-closure`、`~/.agents/skills/work-closure`、`~/.claude/skills/work-closure` 逐文件 SHA256 一致，且与审查通过的版本一致；同一提示启动的新进程必须返回 `WORK_CLOSURE_V2_PRESENT`。
